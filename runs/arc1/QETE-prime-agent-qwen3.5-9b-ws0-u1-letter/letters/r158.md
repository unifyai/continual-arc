## The workflow that works

1. **Read the demo pairs first.** Write down what changed between input and output in plain words before writing any code.
2. **Find the background**: it is almost always the most common color. Nearly every rule is expressed as "something happens to background cells / non-background objects."
3. **Compute connected components** (usually 4-connectivity; sometimes 8 — try 4 first). Most rules are about components: their size, shape, bounding box, count, or position.
4. **Write a `transform(grid)` function** that implements your hypothesis. Test it against every kept demo pair before submitting. A program that reproduces all pairs is your best evidence; a prediction that contradicts no pair but "feels right" is much weaker.
5. **When unsure between hypotheses, pick the one that reproduces all pairs with the least special-casing.** Elegant rules generalize; ad-hoc patch rules don't.

## Rule families I saw repeatedly (study my saved programs)

- **Fill enclosed background pockets** (task-3f4fb1a9): flood-fill background from the border; unreached background regions touching only non-background get recolored (often to 4). Watch for refinements: only *solid rectangular* pockets counted, plus a one-row extension below 2-tall pockets.
- **Separator lines split the grid** (task-026adbf3, task-48898d06, task-bb30ebc2, task-707635df): a full uniform row/column of one color divides the grid into blocks. Output is a per-block verdict: do the two halves agree? odd count of stray color? do 4 corner markers match? Always check whether the separator is *centered* (implies halving) or arbitrary.
- **Stamping / translation** (task-1b7868f1): largest non-background component is a seed; every other non-background cell is an anchor where the seed's bounding box gets stamped (center-to-center). Simple and powerful — check "copy a pattern to each marker" early.
- **Mirroring / tiling** (task-73499f5a, task-794e60f6): outputs are often input + reverse(input), or a 2n×2n quilt of the input and its rotations (TL=input, TR=rot90cw, BL=rot90ccw, BR=rot180). Check symmetric constructions before anything clever.
- **Dot-to-dot filling** (task-5c839a47): the *least common* color marks dots; cells strictly between the min and max dot along a row/column get a fill color. Lone dots stay unchanged.
- **Diagonal ray extension** (task-3b5f776f): contiguous same-color runs of length ≥2 shoot rays along their diagonal/antidiagonal, filling background until blocked.
- **Downward shift** (task-efc2fba8): all non-background cells move down one row; top row becomes background. Trivial rules exist — don't overthink.
- **Object slides toward a line** (task-77262100): the object translates until adjacent to a full line of color 2, and a full line of color 8 is drawn just beyond it.
- **Downscale by sampling** (task-67dd046a): output cell = per-3×3-block mode, ignoring a designated noise color (5). When output dims are input dims ÷ k, think block voting.
- **Recolor by comparison** (task-2264bd4e): map the two colors (keep higher, lower → 0). Sometimes the rule really is that simple.
- **Singleton + twin pairs** (task-0f6e5a2f): one unique large object (e.g. an L/arrow) is a reference; among exact-translation twin pairs of the same shape, the member farther from the reference gets recolored to the reference's color. Generalize: "one special object selects among repeated objects by distance/orientation."
- **Gap filling between markers** (task-8625f9bc, task-b7641a67): fill background runs of small bounded length (≤2 or exactly 1) between two identical/marker cells along rows or columns, plus possibly the bounding-box perimeter.
- **Noise removal / keep the big stuff** (task-b62da9e0): components of size ≥3 get their bounding box filled; everything else reverts to background. "Keep rectangles, drop specks" appears often.
- **Uniform lines recolored** (task-47ed202e): any row or column that is a single repeated color becomes all 2.
- **Cycle of line colors** (task-2e29965a): colored cells lie on parallel lines; the whole grid is filled by cycling those colors along the perpendicular direction, modulo the period.

## Hard-won lessons

- **Special cases are where tasks are lost.** task-5c839a47 cost 8 wrong attempts because the test had a *single* dot while all demos had pairs. If a test input has a configuration never seen in demos (one object instead of many, zero of something, an object at the border), think hard and consider requesting demo pairs before spending submissions on guesses.
- **Request demos strategically.** They're cheap relative to wrong submissions. If two hypotheses both fit the demos, request another pair rather than guessing.
- **Count your wrong attempts.** Some tasks cap them (task-5997d753 hit the cap). Don't burn attempts on "maybe it's X" without pair support.
- **Write the rule in the memory file** after solving, with the exact predicate ("rectangular pockets only", "runs of length ≥2", "strictly between"). Future-you on a recurring variant will thank you.
- **Beware of near-duplicates in failed submissions** — record what you tried (see task-1b7868f1_failed.json: sub1 was a duplicate of sub3; the note listed untried variants like anchoring at a different cell or shifting by one). When a stamping/translation hypothesis fails, try: different anchor (top-left vs center vs seed cell), include vs exclude holes/zeros in the stamp, clip vs wrap at borders.
- **Bg detection**: most-common color works nearly always. But in separator tasks the separator color may itself be common — identify separators structurally (uniform full row/col) not by frequency.
- **Check both orientations.** Any rule about rows usually has a column version (task-77262100 handles both; so should yours). Any rule about "toward the line" has a "from the other side" version.
- **Exact-translation twins**: canonicalize shapes as `tuple(sorted((y-min_y, x-min_x) for ...))` and group by that key to find repeated shapes regardless of position.
- **Colors 1–9 only, 0 often background too** — don't assume background is 0; compute it.

## Quick decision ladder for a fresh task

1. Output dims ≠ input dims? → tiling/mirroring, halving at separator, block voting, or quilt of rotations.
2. Output = input with some cells recolored? → find the predicate: enclosed regions, gaps between markers, uniform lines, cells between dots, farther twin.
3. Objects moved? → slide toward a line, stamp seed at anchors, shift by one.
4. Noise? → component-size threshold, mode per block, drop non-rectangles.
5. Nothing obvious? → sort colors by frequency; the rarest color is usually the protagonist; trace what happens to it.

Trust pairs over intuition, keep programs small and general, record your rules, and save your memory files — the harness gives them back to you. Good luck.
