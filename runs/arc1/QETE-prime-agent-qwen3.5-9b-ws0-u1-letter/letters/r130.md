## 1. The general workflow that wins

For each new task, follow this loop:

1. **Read the demo pairs from the program JSON files first.** Before writing any rule, look at the actual grids. Stare at input vs output cell by cell. Count colors.
2. **Find the background color** (most common). Almost every task has one; it's the "empty" color, often but not always 0.
3. **Name the objects.** Connected components (4- or 8-connectivity — try both, some tasks are 8-connected like task-1b7868f1), their colors, sizes, bounding boxes, shapes. Ask: how many components of each color? Are any of them exact copies (translations) of each other? Are any rectangles, lines, L-shapes, hollow rectangles?
4. **Guess the simplest rule first.** ARC rules are usually simple: recolor, translate, stamp, fill, count, extend, mirror, tile. Complex rules are usually wrong; if you need 40 lines with many special cases, you're probably overfitting.
5. **Write a `transform(grid)` function** that reproduces every kept demo pair. Test it on all of them before submitting a prediction. A program that reproduces 4/4 demos is trustworthy; one that reproduces 3/4 is not.
6. **Save your program to `programs/task-<id>.py` and the demo pairs to `programs/task-<id>.json`**, then write a memory entry. Keep the rule description in memory — one day you'll meet the same *kind* of task again, and reading "fill enclosed background pockets with 4" instantly primes you.

## 2. Rule families I actually solved — memorize these signatures

These are real rules from my stream. When you see a similar setup, check these first:

- **Shift down one row** (task-efc2fba8): all non-background cells move down by 1; original cells become background. Output looks almost identical to input but everything dropped one row.
- **Fill enclosed background regions with a fixed color** (task-3f4fb1a9): find background components that don't touch the border; if rectangular, fill with 4 (or the task's fill color). Watch for subtle extras — in mine, 2-row pockets also absorbed the wall row below them under a condition.
- **Hollow rectangles get filled by parity** (task-aa5a69a0): components that are perfect rectangular outlines (perimeter of their bbox) get interior filled with color X if area even, color Y if odd. This "parity pick" pattern (even→one color, odd→another) appears in multiple tasks.
- **Stamp the largest object at every anchor** (task-1b7868f1): the largest non-background component is a "seed"; every other non-background cell is an anchor point; stamp the seed's bounding box translated so its center lands on each anchor, overwriting background.
- **Rare-color shape stamped where it fits in zeros** (task-770f2daf): find the rarest color's shape; try all offsets; where all its cells land on 0/background, paint them.
- **Object slides until it touches a line, then a line is drawn on the far side** (task-77262100): a full row/column of color 2 is a rail; the object moves adjacent to it; a full line of color 8 is drawn just beyond the object's far side, overwriting background only.
- **Two parallel bars of one color, dots of another between them** (task-d4079843): from the bar facing the dots, draw a line through each dot (dots become 4); from the opposite bar, draw matching lines spanning the gap. The offsets from bar-start to dots are reused on the mirror bar.
- **Split by a solid separator row/col** (task-026adbf3, task-707635df): a full uniform row/column of one nonzero color splits the grid into two same-size blocks A and B. Common outputs: cellwise comparison (3 where equal, else background), or AND of the two nonzero masks recolored to 2.
- **Grid of blocks separated by solid lines; each block collapses to one cell** (task-bb30ebc2, task-48898d06, task-67dd046a): find rows/columns that are one solid color (separators); the remaining bands define blocks; each block reduces to a single cell by majority vote, odd-count detection, or corner-color agreement. Output is tiny (e.g. 4×6).
- **Whole-row/whole-column uniform ⇒ recolor to 2** (task-47ed202e): rows or columns consisting of one repeated color become all 2.
- **Background between two identical neighbors becomes 2** (task-b7641a67): scan rows; `bg` cell with equal non-bg cells on both sides → 2.
- **Fill bbox of components ≥ size 3 with their color, erase everything else** (task-b62da9e0): noise dots (size 1–2) vanish; real objects get their bounding boxes filled solid.
- **L/angle shapes and twin pairs** (task-0f6e5a2f): a singleton large thin angle is an "arrow"; among exact-translation twin shape pairs, recolor the twin *farther* from the arrow to the arrow's color. Key idea: classify shapes (line vs angle) and find translation-twins via canonical sorted relative coordinates.
- **Diagonal periodic pattern** (task-2e29965a): if nonzero cells repeat a pattern along diagonals (constant along `r+c mod L` or `r-c mod L`), tile the whole grid with that diagonal period.
- **Mirror + tile** (task-73499f5a, task-794e60f6): output = `row[::-1]+row` per row, then stack reversed/original/reversed (height triples); or 2×2 tiling with rotations (TL=orig, TR=rot90, BL=rot270, BR=rot180).
- **Extension of a line** (task-3b5f776f): an endpoint cell (degree-1 in 8-connectivity among non-bg) extends in its own direction until the border.
- **Row/col-spanning fill between dots** (task-5c839a47): fill with 3 strictly between the min and max of the rarest color per row and per column. (See the failure section below for its caveat.)

## 3. Diagnosing a rule: concrete techniques

- **Diff the grids.** Mark cells that changed and cells that didn't. What shape is the changed set? A region? Lines? Scattered points? A translated copy of something?
- **Count colors in vs out.** If a color disappeared, something got recolored to something else. If a new color appeared (like 4 or 2 or 3), find the *smallest* example where it appears and study just that.
- **Use the smallest demo pair** as your laboratory. Small grids reveal mechanics; big grids confirm generalization.
- **Check invariance.** Often large parts of the output equal the input. Identify exactly what's preserved — that's the background and untouched objects.
- **Connectivity matters.** Decide 4 vs 8 connectivity by testing both; components that look separate under 4-connectivity may be one object under 8.
- **Bounding boxes are everywhere.** Fill the bbox, stamp the bbox, extend to the bbox edge, distance to a bbox — try bbox-relative coordinates (`min_y, min_x` normalization) whenever comparing shapes.
- **Canonical shape key** for comparing objects: `tuple(sorted((y-min_y, x-min_x) for y,x in cells))`. Exact-translation twins have identical keys. This one function solved a whole task for me.

## 4. How to use your attempt budget

You typically have a limited number of submissions per task, and you can request more demo pairs. My lessons:

- **Never submit a prediction your program doesn't reproduce on all kept demos.** Every single wrong submission I made came from either (a) guessing beyond the demos, or (b) a lone/ambiguous case the demos didn't cover.
- **When the test input has a configuration absent from the demos (like a single dot when all demos had many), that's your highest risk.** If demos can be requested, request them *early* — I burned 8 wrong attempts on task-5c839a47 trying identity, cross, row-only, col-only, mirror, etc., before realizing I should have asked for demos on turn one. The memory file even says it now: "if a test has a single dot / lone-object, request demos early."
- **When two rules fit the demos equally well, prefer the one that also handles the test input's edge case gracefully**, or ask for a demo that discriminates.
- **Don't repeat rejected predictions.** Track wrong attempts in a status file. On task-1b7868f1 I wasted submissions on near-duplicate variants; a note like "clean anchors (13,7),(12,8) untried" saved me later — write such notes *before* you forget.

## 5. Coding habits that saved me

- Write `transform(grid)` taking a list of lists of ints, returning the same. The harness expects that.
- Background = `Counter(v for row in grid for v in row).most_common(1)[0][0]`.
- Copy before mutating: `out = [row[:] for row in grid]`. Mutating while reading the original is a classic bug — read from `grid`/`g`, write to `out`.
- Keep small helpers: component finder (both connectivities), bbox, canonical shape key, separator-row/col finder, band/block splitter. You'll reuse them every task.
- Guard your rule: if the expected structure isn't found (no separator, no twin pair, no arrow), **return the input unchanged** rather than crashing. A wrong-but-returned answer is better than an exception.

## 6. Mindset

ARC tasks reward *looking* before *thinking*. The answer is usually visible in one demo pair if you compare carefully: something moves, something fills, something copies, something counts. Resist inventing elaborate machinery. When stuck, re-examine the smallest example and ask "what is the single most obvious difference between input and output?" It is almost always that.

And when you solve a task, write the memory entry with the rule in one sentence. Future-you, playing the stream, will thank present-you.

Good luck. Look carefully, test everything, and may your backgrounds be common and your objects well-connected.
