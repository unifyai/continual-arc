## 2. General strategy per task

1. **Inspect before theorizing.** Count colors; find the background (most common). List components (usually 4-connected, same color). Compare input and output *cell by cell* on demo pairs — diff the grids and look at only the changed cells. Most rules are simple relations on those diffs.
2. **Check output shape first.** Many tasks change dimensions (downscale to a block grid, double/triple by mirroring, split halves). If output dims differ from input, the rule is geometric — compute the ratio immediately. Examples from my run: 3x downscale by majority per 3x3 block; 2x2 tiling of the input and its rotations; splitting at a centered solid separator line and comparing halves; each row becomes reverse+itself with height tripled by mirror-stacking.
3. **Prefer the simplest rule consistent with all demos.** When two rules both fit, the simpler one wins the test more often. But if a test fails, don't double down — enumerate the *next simplest* variations. Keep the failed list so you don't resubmit a near-duplicate.
4. **Symmetry and repetition are everywhere.** Diagonal/anti-diagonal runs extended to grid edge; periodic color assignment along diagonals (infer period from given lines); tiling a found pattern across separator-delimited regions; a pattern stamped at every anchor cell.
5. **Careful with "least common color" logic.** Several tasks key on the rarest color (dots). A recurring pitfall: a *single* lone dot in the test input. My rule "fill strictly between min and max dot per row/column" was correct for 10 demos but the test with one dot needed something else, and I burned 8 attempts guessing. **If your demos all have ≥2 dots but the test has 1, stop and think hard, or request demos** — degenerate test cases are where simple rules break.

## 3. Recurring rule families (with the exact patterns that worked)

- **Diff-map tasks:** grid split by a full uniform row/column into two same-size blocks; output marks cells where the halves agree/differ (or where both hold their dominant color). Find the separator as a row/col where all cells share one value; check it's *centered* if output is half-size.
- **Line/region grids:** full solid separator rows/columns divide the grid into blocks; output is one value per block (majority, odd-count of a stray color, or the block value where four corner markers agree). Build band lists, then a small output matrix indexed by (row-band, col-band).
- **Seeds and arrows:** one special component (largest, or unique color, or L-shaped singleton) is a reference; other objects get recolored, moved, or mirrored relative to it. Tie-breaks often use "nearest," "farther member of the twin pair," or "larger size" — test each on the demos.
- **Draw/extend:** extend same-color runs (rows, columns, diagonals) until blocked; complete broken straight lines of marks; fill bounding-box borders; fill enclosed rectangular pockets of background. For "enclosed," flood-fill background regions touching the border and exclude them.
- **Stamp/translate:** find the largest non-background component (the seed); for every other non-background cell, stamp the seed's bounding box translated so its center lands on that cell. Include background and holes inside the bbox as-is.
- **Move toward a line:** an object slides until flush against a solid color-2 line; a new full-length line of a different color is drawn on the object's far side.
- **Cleanup:** components of size ≥3 (or ≥3-cell) are kept and grown to full bounding rectangles; everything else becomes background. Or: complete broken lines of the mark color inside the bbox.

## 4. Code patterns worth copying

Copy these verbatim; they are correct and I used them in nearly every task:

Background + components (4-connected flood fill):

```python
from collections import Counter, deque
def comps(g, bg=None):
    H,W=len(g),len(g[0])
    if bg is None:
        bg=Counter(v for r in g for v in r).most_common(1)[0][0]
    seen=[[False]*W for _ in range(H)]; out=[]
    for i in range(H):
        for j in range(W):
            if g[i][j]!=bg and not seen[i][j]:
                q=deque([(i,j)]); seen[i][j]=True; c=[]
                while q:
                    y,x=q.popleft(); c.append((y,x))
                    for dy,dx in((1,0),(-1,0),(0,1),(0,-1)):
                        ny,nx=y+dy,x+dx
                        if 0<=ny<H and 0<=nx<W and not seen[ny][nx] and g[ny][nx]!=bg:
                            seen[ny][nx]=True; q.append((ny,nx))
                out.append(c)
    return bg,out
```

Solid separator rows/cols: `rb=[r for r in range(H) if len(set(g[r]))==1]`, same for columns. Bands of consecutive non-separator indices (group runs of consecutive integers).

Canonical shape key for comparing object shapes under translation:
```python
def key(cl):
    ys=[y for y,_ in cl]; xs=[_,x for _,x in cl]  # fix: xs=[x for _,x in cl]
    return tuple(sorted((y-min(ys),x-min(xs)) for y,x in cl))
```
Group objects by this key to find twin pairs, count occurrences, etc.

Verification loop — always run before submitting:
```python
for pair in demos:
```

## 5. Mistakes I made — avoid these

- **Submitting without verifying against every kept demo.** Once I submitted a program that was actually identical to a previously failed one; the note file showing "sub1==sub3 duplicate" would have prevented it.
- **Not saving failed hypotheses.** Enumerate candidate rules in a file with status (tried/failed, untried). Return to that list, in order, on each new attempt.
- **Overfitting weird constructions** when a plain rule fit. If a rule needs three special cases to explain one demo, it's probably wrong; look for a different framing (e.g., "the anchor is the seed's *bbox center*," not "an arbitrary cell of the seed").
- **Ignoring degenerate test inputs** (lone dots, all-one-color rows, single component). Check the test input's structure against your demos' structure before submitting. If they differ qualitatively (counts of the rare color, presence of the separator, etc.), request demos or reason explicitly about the degenerate case.
- **Forgetting that 8-connectivity vs 4-connectivity matters.** One of my seed-stamping solutions used 8-connected components (diagonals join). Check both if one doesn't separate the objects the way the puzzle implies.
- **Wasting demo requests.** Ask for demos when genuinely stuck *early* (before burning attempts), not after. Two or three demos usually disambiguate among your top candidate rules.

## 6. When you're stuck: a checklist

- Diff demo in/out; list changed cells and their colors.
- Does output shape change? If yes, what ratio/operation?
- Background most-common color; is it preserved?
- Are components preserved, recolored, moved, mirrored, or deleted?
- Separator lines (solid rows/cols)? Bounding boxes of objects?
- Symmetries: rows, columns, diagonals, 180° rotations, mirror+tile?
- Rarest color as marker/seed? Its count matters (≥2 vs =1).
- Count-based rules: odd/even counts, majority, "exactly twice" pairs.
- If nothing fits: try rotational/mirrored variants of your best rule; try the rule applied only inside some region (enclosed areas, blocks between separators).
