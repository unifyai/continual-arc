## The workflow that works

1. **Ask for demo pairs early and often.** Your program is only as good as the pairs it reproduces. I consistently kept 2–8 pairs per task and verified the program against *all* of them before submitting a test prediction. A program that reproduces every kept pair is your best evidence the rule is right.
2. **Save your program and pairs to files** (e.g. `programs/task-<id>.py` and `.json`), and write a memory file stating the rule in one sentence. When a later instance of the same task appears, load the saved program and run it on the new test input — this solved several of my tasks at zero cost.
3. **One wrong attempt on a test is expensive.** If your rule involves an unresolved special case (a lone marker, a degenerate input), resolve it *before* submitting, even if that means requesting more demos. I lost a task (5c839a47) because the test had a single dot and every lone-dot guess I tried was wrong; the demos all had ≥2 dots and couldn't disambiguate.

## The rule catalog

ARC rules cluster into families. Scan this list mentally when you see a new grid:

- **Structural grid splits.** Full uniform rows/columns are separators. Blocks between separators become one output cell (48898d06: count stray pixels per block, 1 if odd/≥2 else bg). A centered separator row/col splits the grid in halves; compare cells positionally (707635df: 2 where both halves hold their dominant color; 026adbf3: 3 where A==B else the blocks' shared color).
- **Guides at intersections.** bb30ebc2: grid split by guide rows/cols; output cell = value found at the four corners of each block if all four markers agree, else background. Mosaic-style outputs are common.
- **Stamping / tiling.** A largest component is a seed; every other non-background cell is an anchor where the seed's bounding box gets stamped (1b7868f1). Or a rare color's bounding-box pattern is stamped into every empty box of that size (770f2daf). Or the input tiles itself: block of I, rot90, rot90², rot90³ (794e60f6); or each row becomes reverse(r)+r and the stack is mirrored (73499f5a).
- **Periodicity.** If colored lines are on anti-diagonals (i+j constant), infer the period and tile the color along that diagonal family (2e29965a). Check row-, column-, diagonal-, and anti-diagonal-periodicity whenever sparse colored cells appear.
- **Directional extension.** Runs of length ≥2 of the same color extend along their diagonal/anti-diagonal until blocked (3b5f776f). Between min and max positions of the rarest color per row and per column, fill a new color (5c839a47).
- **Enclosed regions.** Background components that don't touch the border and are exactly rectangular get filled with a new color (3f4fb1a9). Watch for extra conditions (e.g., also fill a slot below 2-tall pockets).
- **Objects move / align.** An object shifts to become flush against a colored line, old footprint becomes background, and a new full line of another color is drawn on the object's far side (77262100). Or the object gets clipped at an edge and a second, shifted copy is completed (5997d753: find the best cyclic/linear shift between bands by overlap; fill where the reference pattern extends beyond the clipped copy).
- **Recolor by relationship.** Singleton large shape = arrow; among twin-shape pairs (same canonical shape exactly twice), recolor the member farther from the arrow (0f6e5a2f). Two colors only: keep the higher, zero the lower (2264bd4e). Full uniform rows/cols get recolored (47ed202e). Marker-color cells within a box's bounding region get 2-filled (8625f9bc).
- **Lines and stubs.** Seed dots of one color, bars of another: each dot draws a stub toward the nearest bar and becomes 4; a mirror line is drawn on the other bar at the clamped index (d4079843). Fill gaps between same-row markers with a fixed color (b7641a67).
- **Component filtering.** Components of size ≥3 have their bounding box filled; everything else returns to background (b62da9e0). Small ring-shaped components (perimeter shape, both dims ≥3) get their interior filled with 2 or 7 depending on parity (aa5a69a0). Dots shift down one row (efc2fba8).
- **3×3 downscaling.** Divide into 3×3 blocks, take the most common non-noise color per block (67dd046a).
- **Shift all content down one row** (efc2fba8) — simple rules exist too; don't overcomplicate.

## Practical heuristics

- **Background = most common color**, almost always. Non-background cells define the objects.
- **Count colors and components first.** The rarest color is usually the trigger; the most common non-bg is usually the payload. A color occurring exactly once or twice as a component is special.
- **Canonicalize shapes** (sorted relative offsets from bbox min) to find twins/duplicates; use translation-invariant comparison when positions differ.
- **Check separability early:** scan for full uniform rows/cols, centered separators, exact 3×3 divisibility, and periodic diagonals before inventing anything fancier.
- **Tie-breaks matter.** When two candidate rules both fit the demos, prefer the simpler one, and consider what distinguishes them on the test input — then pick the interpretation that handles degenerate cases gracefully (identity is often wrong; so is over-eager action).
- **Reuse across tasks:** the same families reappear with different colors and sizes. My `programs/` directory contains working `transform(grid)` functions for every solved task — adapt them freely.
- **When a program reproduces all demos but you're unsure on the test,** write the rule in the memory file with explicit note of what's unresolved, so a future instance (or future you) can settle it cheaply with a demo request instead of a wrong submission.
