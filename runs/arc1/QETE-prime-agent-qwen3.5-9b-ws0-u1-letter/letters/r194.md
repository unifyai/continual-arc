## 1. The harness loop, and how to spend your attempts

- You get a test input with no visible output. You write `transform(grid)` in a program file, run it mentally (or via saved data), submit a prediction, and are told wrong or right. Wrong attempts are expensive — some of my tasks died at the 8-attempt cap.
- The cheapest resource is **demo pairs**: saved examples you can request and keep in `programs/task-XXXX.json`. If your rule reproduces every kept pair exactly, your rule is probably right, and the only risk is generalization to the test's edge case.
- **Before submitting, verify your program reproduces every kept demo pair.** I lost a task (5c839a47, the "lone dot" one) because my program fit all 10 demos but I guessed wildly on the test. If the test input has a *degenerate* case your demos never show (one dot instead of several, an empty region, a shape clipped by the border), and you have wrong-attempt budget, request more demos or reason carefully about the degenerate case instead of burning attempts.

## 2. A reliable working method

1. **Find the background** — almost always the most common color. Everything else is signal.
2. **Inventory the non-background objects**: connected components (decide 4- vs 8-connectivity; try 4 first), their colors, sizes, and how many times each shape recurs.
3. **Count occurrences.** Rules almost always key on cardinality: "the component that occurs exactly twice", "the singleton large angle", "the least common color". My solved tasks include: recolor the *farther* of a twin pair from a singleton arrow (0f6e5a2f); stamp the *largest* component's bbox at every other non-bg cell (1b7868f1); the *rarest* color's pattern tiles into empty boxes (770f2daf).
4. **Look at what changes between input and output in each demo.** Diff them cell by cell. Usually only a small set of cells changes, and the change is one of a small vocabulary:
   - recolor some cells (a fill color, or the target color of some anchor object);
   - translate/copy a shape (often stamped at anchor points, or mirrored/rotated/tiled);
   - extend lines (runs along rows/cols/diagonals grow until blocked — 3b5f776f);
   - fill enclosed regions (background pockets inside a bounding ring get a specific color — 3f4fb1a9, aa5a69a0);
   - draw bounding boxes or complete broken straight lines (8625f9bc);
   - move an object flush against a line, and draw a marker line on its old side (77262100);
   - downsample blocks to a summary statistic (67dd046a: majority non-noise color per 3×3; 48898d06: parity/count of strays per block);
   - structural symmetry ops: mirror-and-concatenate, kaleidoscope tiling with rotations (73499f5a, 794e60f6), periodic tiling along a diagonal with inferred period (2e29965a).
5. **Write the rule as a program, run it on the demos, and only submit when zero mismatches.**

## 3. Recurring structural templates worth pattern-matching instantly

- **Separator lines.** Full rows/columns of one uniform color split the grid into blocks. Many tasks compare blocks: equality across halves → output 3 (026adbf3), count strays per block (48898d06), majority color per block (67dd046a), find the "off-pattern" block and tile its pattern everywhere (8d84fe63), guide-line intersections pick colors (bb30ebc2). Learn the idiom: `sep_rows = [r for r in range(H) if len(set(grid[r]))==1]`, likewise columns; then compute contiguous bands between them.
- **Rows/columns that are uniform get marked** (all 2s in 47ed202e) — check this before inventing anything fancier.
- **Twin shapes.** If a canonicalized shape (sorted normalized cells) occurs exactly twice, one of them is usually the "special" one and gets recolored, moved, or is the source for a stamp. Tie-break by size, then by distance to some singleton anchor object.
- **Singleton anchor = target color donor.** A unique component (often largest, or a distinctive thin shape) often dictates the color other objects become, or the point other things point to.
- **Directional growth.** Diagonal/antidiagonal runs (r−c, r+c), row/col runs, and "extend until blocked by non-background or edge" show up repeatedly. Implement it as a loop along the direction with a boundary check — cheap and safe.
- **Kaleidoscope/symmetry completion.** If the input is roughly symmetric with noise, output often is the input with each cell snapped to the symmetric consensus. If the input shows periodic structure, infer the period from the colored cells and tile (2e29965a's approach: group by i+j, i, or i−j; check each group is monochrome; infer assignment mod p).

## 4. Programming hygiene in the harness

- Save every solved program as `programs/task-<id>.py` with a `transform(grid)` function, and every kept demo in `programs/task-<id>.json`. Write a short memory file stating the rule in one or two sentences — my memory files have repeatedly rescued me when a task family returns.
- **Cross-task contamination warning:** occasionally a "demo pair" that arrives belongs to a different task (I logged this on 3f4fb1a9). If a pair doesn't fit your rule no matter what, check whether its structure is alien before concluding your rule is wrong.
- Handle the degenerate cases in code explicitly: empty grids, no non-background cells, a single instance of the key object, shapes clipped at the border, grids where the separator is off-center. Raise a clear exception rather than silently returning the input — a visible crash is better diagnostic than a plausible-looking wrong answer.
- Prefer deterministic, purely local rules over numeric coincidence. "Cells strictly between the min and max dot per row/column" (5c839a47) beat "count strays ≥ 2" style thresholds only after I checked all demos — always test thresholds against every kept pair.

## 5. Psychology of guessing

- If several rules all reproduce the demos, pick the one that is *simplest and most symmetric*, and that has a natural answer for the test's degenerate feature. Symmetry of intent is the best tiebreaker.
- Keep a note file like my `task-1b7868f1_failed.json`: list which hypotheses you've already burned attempts on. Never resubmit a near-duplicate hypothesis (I recorded "sub1==sub3 duplicate" as a lesson).
- When a test seems to break your rule at one specific cell or object, localize the discrepancy — often it's one special case (a pocket that isn't rectangular, a shape not touching the border) and the fix is a condition, not a new theory.
