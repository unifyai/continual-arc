## 1. The core workflow (do this every task)

1. **Read the demo pairs carefully, one at a time, cell by cell for small grids.** Don't guess from a glance. The rule is usually simple once you see it, but "usually simple" means you must actually verify, not squint.
2. **State a hypothesis in words before coding.** Write it down. Then check it against EVERY kept pair mentally or with the program.
3. **Write the program, run it against all kept pairs, and only submit when it reproduces all of them.** A program that reproduces all demos is your best evidence; a program that reproduces "most" demos will usually fail the test.
4. **When the demos admit multiple rules, prefer the simplest one that fits all pairs**, but check the alternates before committing a submission — wrong submissions are expensive (see the failed-attempt notes in memory files like task-5997d753, which hit the attempt cap).

## 2. Rules I've already seen (check these first)

Many tasks reuse a small family of ideas. Before inventing something new, test whether the task is one of these:

- **Background detection**: the most common color is the background. Almost every task uses this. `Counter(x for row in grid for x in row).most_common(1)[0][0]`.
- **Connected components** (4-connectivity is right far more often than 8; but task-1b7868f1 used 8-connectivity — verify per task). Find components of non-background colors, look at their shapes, counts, bounding boxes.
- **Recolor by min/max color**: with exactly two non-background colors a<b, sometimes a→b and b→0 (task-2264bd4e). Role-based rules (majority→X, minority→Y) failed there; the min/max rule won. When two candidate rules both fit demos, they may diverge on the test — think about which generalizes.
- **Fill enclosed regions**: background regions not touching the border (flood fill from border to find the outside), possibly only if rectangular, possibly with special cases for 2-row-tall pockets absorbing their bottom wall (task-3f4fb1a9). Watch for pockets that are non-rectangular — the rule often excludes them.
- **Hollow rectangles**: find rectangle outlines; fill interior, sometimes with a color chosen by a property of the interior (parity of area → 2 if even else 7, task-aa5a69a0).
- **Stamp/translate a seed**: the largest (or otherwise distinguished) component's bounding box gets stamped, translated, so that its center lands on every other non-background cell (task-1b7868f1). Stamping must copy the bbox as-is including holes/other colors.
- **Diagonal periodic fill**: colored cells are clues on diagonals; fill the grid with P[(r+c) mod L] or P[(r−c) mod L], L = number of distinct nonzero colors (task-2e29965a). Try both diagonal directions; pick the one consistent with the clues.
- **Separator lines split the grid**: full uniform rows or columns (single color, full extent, not the region color) divide the grid into blocks. Common outcomes: (a) compare two same-size blocks cellwise, output 3 where equal else the shared background (task-026adbf3); (b) AND of two regions' nonzero masks, recolored (task-707635df); (c) each block collapses to one cell by counting stray pixels — parity or threshold (task-48898d06: output 1 if odd count of stray color else background); (d) tile the one "content" block into all blocks (task-8d84fe63); (e) output is just one block extracted from the corner farthest from clutter.
- **Line/coloring between anchors**: background cell strictly between two identical non-background cells in its row (or column) becomes a fixed color, often 2 (task-b7641a67, task-47ed202e — uniform rows/cols of the line color become 2; task-5c839a47 — between dots of the rarest color in row OR column becomes 3). Also: fill gaps between runs of ≥2 markers along rows/columns and the marker bbox perimeter (task-8625f9bc).
- **Symmetry/mirror constructions**: rows mirrored and doubled, then stacked reversed/original/reversed (task-73499f5a: each row becomes reverse(r)+r; stack = reversed rows, original, reversed again). Or the output is a 2×2 block of the input and its three rotations (task-794e60f6: [[I, rot90cw],[rot90ccw, rot180]] via np.block). Or every row shifted down one with the top row becoming background (task-efc2fba8 — trivially simple once spotted; check whole-row-shift first when the output is the input moved).
- **Object moves toward a line**: an object slides until adjacent to a full separator line (color 2), and a full line of another color (8) is drawn on the object's far side, overwriting only background (task-77262100). Handle both orientations and both sides.
- **Bar + dots construction**: two bar segments of one color, scattered dots of another; draw perpendicular lines from the bar facing the dots through each dot (dots become 4), and parallel full-gap lines from the other bar at the same offsets (task-d4079843). Note the offsets are measured relative to the bar's start, not its near edge — this detail decided correctness.
- **Twin shapes + arrow**: among exact-translation twin pairs (same canonical shape occurring exactly twice), pick the pair by proximity to a distinguished object (a large thin angle = arrow), recolor the farther member to the arrow's color (task-0f6e5a2f). Canonicalize shapes as sorted relative coordinates to detect translation-twins.
- **Min/max recolor to 0**: one color maps to 0, the other to the other (task-2264bd4e: smaller→larger, larger→0).
- **Row replication from a seed with shift search**: when a bottom block repeats a top block, background cells in the bottom that align with pattern cells in the top become a fixed color; find the alignment by trying all shifts and scoring (penalize pattern-covers-background mismatches first — see task-5997d753, which I never fully cracked; the scoring tiebreaks matter and I burned 8 wrong attempts there. Lesson: when the rule is "align and transfer," enumerate shifts and pick by explicit, defensible scoring; test scoring variants on demos before submitting).
- **Sparse "true grid" extraction**: grids full of noise color X with a few cells of other colors — keep only cells of the non-dominant colors, or downscale by 3 taking the most common non-separator color per 3×3 block (task-67dd046a).
- **Cellwise diff of two halves**: split by separator, compare A and B; equal → 3 (or another fixed color), unequal → the common background (task-026adbf3).

## 3. Pitfalls that cost me attempts

- **Verify against ALL kept pairs, always.** A rule that fits 3 of 4 pairs is wrong. The task-1b7868f1 failed file shows I submitted near-duplicates because two variants looked the same on some pairs — I then noted in the file which alternates remained untried ("clean anchors (13,7),(12,8) and (12,7)+0→1 untried"). Keep such notes: when a submission fails, record exactly which variants you tried and which remain, so you don't resubmit a duplicate.
- **Distinguish translation-twins from rotation/reflection-twins.** Canonicalize by sorted (r−min r, c−min c) tuples for pure translations; if that finds no pair, try canonical forms under dihedral symmetry.
- **Offset conventions matter.** "Relative to bar start" vs "relative to near edge," "center maps to anchor" vs "top-left maps to anchor." If your program fails demos by one cell, this is the first thing to check.
- **Background color for the output** is usually the input's background, but check (some tasks use input[0][0] specifically, which usually coincides but not always).
- **Don't overfit to one demo pair.** If you only have 1–2 pairs, prefer the rule that would obviously generalize; avoid conditions keyed to incidental details (exact colors where the rule is clearly structural, exact sizes where the rule is "any pocket").
- **Program output must be JSON-serializable plain lists of ints** — convert numpy types (`int(...)`) if you use numpy.

## 4. Code templates worth memorizing

Background:
```python
from collections import Counter
bg = Counter(x for row in grid for x in row).most_common(1)[0][0]
```

4-connected components of non-background:
```python
seen=[[False]*W for _ in range(H)]; comps=[]
for r in range(H):
    for c in range(W):
        if grid[r][c]!=bg and not seen[r][c]:
            stack=[(r,c)]; seen[r][c]=True; comp=[]
            while stack:
                y,x=stack.pop(); comp.append((y,x))
                for dy,dx in ((1,0),(-1,0),(0,1),(0,-1)):
                    ny,nx=y+dy,x+dx
                    if 0<=ny<H and 0<=nx<W and not seen[ny][nx] and grid[ny][nx]==grid[r][c]:
                        seen[ny][nx]=True; stack.append((ny,nx))
            comps.append(comp)
```
(For "all non-background colors form one object regardless of color," flood over `grid[ny][nx]!=bg` instead of matching color — task-1b7868f1 did that.)

Separator rows/cols:
```python
sep_rows=[i for i in range(H) if len(set(grid[i]))==1]
sep_cols=[j for j in range(W) if len(set(grid[i][j] for i in range(H)))==1]
```
Then group consecutive indices into bands and process blocks between them.

Enclosed region check: flood from all border background cells; anything not reached and not on the border is enclosed.

Rectangle outline test: bbox with `len(comp)==2*(h)+2*(w)-4` and all cells on the bbox perimeter.

## 5. Habits

- Save a memory file per task (`task-<id>.mem.json` or via the harness memory) with: files, whether the program reproduces all kept pairs, and a one-sentence rule. Future-you (and the grader) benefit enormously; several of my entries literally encoded the winning rule.
- When you save demo pairs to `task-<id>.json`, keep them in the harness format (list of {"input":…, "output":…}); you'll re-verify against them repeatedly.
- If the rule seems to need many special cases, step back — the true rule is usually 1–3 sentences. Special-case sprawl is a smell that you've misread the demos.
- If two rules both fit all demos, compute both predictions on the actual test input; if they agree, submit confidently; if they differ, pick the one whose *mechanism* (not its accidents) explains the demos.
- Time-box exploration: inspect → hypothesize → code → verify loop should be tight. Most tasks here yielded to 10 minutes of careful looking.

The single highest-leverage skill: **read the demo output and ask "what is different from the input, exactly, cell by cell?"** The diff is the answer. Everything above is just the catalog of diffs I've seen so far. Yours will grow the catalog further.
