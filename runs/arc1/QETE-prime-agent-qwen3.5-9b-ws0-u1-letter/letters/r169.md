## 2. Rule families that recur (when you see these, think of these)

- **Grid partitioned by separator lines** (a full uniform row/column of one color, often the least-common color): output is usually a small summary — one cell per block, containing 1 if the block holds a marker (even one), else the background. I solved task-48898d06 this way.
- **Two same-size blocks split by a centered separator**: compare cell-by-cell. Output a marker color where they agree, background elsewhere (task-026adbf3). Or: cell = 2 where each half has its own dominant color at that position (task-707635df).
- **Dominant background + scattered small objects**: the largest object is usually the seed/stamp; every other non-background cell is an anchor where the seed's bounding box gets stamped, centered on it (task-1b7868f1). Or: extend same-color diagonal/anti-diagonal runs of length ≥2 until blocked (task-3b5f776f).
- **Symmetry/mirror fractals**: a square input becomes output = input + mirrored variants. Look for exact reversal structure: rows become `row[::-1] + row`, stacked as `block + reversed(block) + block` (task-73499f5a); or the 2n×2n output made of rotations (TL=input, TR=rot90, BL=rot90ccw, BR=rot180) (task-794e60f6).
- **Enclosed background regions**: flood-fill background components; those not touching the border are "pockets" — fill them with a fixed color (usually 4), sometimes with an extra recoloring of an adjacent wall row (task-3f4fb1a9).
- **Line/arrow anchors and direction**: a singleton long thin shape is an "arrow"; among twin shapes (same canon shape appearing exactly twice), recolor the farther member to the arrow's color (task-0f6e5a2f). Generalized: distance from a special object decides which of a twin pair changes.
- **Dots and connectors**: least-common color cells are dots; fill cells strictly between the min and max dot per row and per column (task-5c839a47). Gaps ≤2 between marker cells along rows/columns get filled (task-8625f9bc).
- **BoundingBox completion**: fill background cells on the bounding box of the marker color and small gaps between marker runs (task-8625f9bc).
- **Shape moves relative to a line**: an object shifts to sit flush against a full vertical line; its old area becomes background and a full line of a new color is drawn at the old position (task-77262100). Or: shift all non-background cells down one row (task-efc2fba8 — trivially simple, and I nearly overthought it).
- **Nested/recursive grids**: the input may contain a drawn grid inside; extract subgrid structure at 1/3 scale or map blocks by corner colors (task-67dd046a, task-bb30ebc2, task-48898d06).
- **Separators recolored**: rows or columns that are uniform become a fixed color (task-47ed202e).
- **Cyclic color patterns along diagonals**: colored cells lie on lines (anti-diagonal, row, diagonal); the line colors tile the whole grid modulo the number of lines (task-2e29965a).

## 3. Heuristics for finding the rule

1. **Count colors first.** Background = most common. The rule usually involves the second-most-common ("marker/line") and least-common ("dot/seed") colors.
2. **Check for full uniform rows/columns** — that means the grid is partitioned; the output is almost always a block-summary or block-comparison.
3. **Check exact dimensions**: output height/width vs input. Output same size → local recolor/extend. Output half or third → block summary. Output double/triple → mirror/tiling. Output = one block's size → extract a block.
4. **Find connected components** (4-connectivity usually; but be careful, some tasks use 8-connectivity — my task-1b7868f1 program uses 8). Compare canonical shapes: shapes occurring exactly twice, or a unique largest shape, are special.
5. **Beware single-cell and single-object degeneracies.** A program that reproduces all demos can still fail the test if the test lacks the structure your rule keys on (two dots, a twin pair, etc.). If the test input lacks the demo structure, stop and request demos instead of guessing.
6. **When several rules fit the demos, prefer the simplest** — recolor, shift, fill — before compound rules. And when demos are thin (1–2 pairs), a compound rule with a free parameter is a coin flip; get more demos.
7. **Simplicity in output color**: the fill color is very often 4, or the arrow/line color, or a fixed small digit. Don't derive it elaborately if a constant works.

## 4. Coding hygiene

- Wrap everything in `def transform(grid):` returning a list of lists. Use `[row[:] for row in grid]` for copies; never mutate the input.
- Write the component-finding helper once per file (flood fill with a deque or stack); it's ~10 lines and you'll need it in half the tasks.
- Verify against every saved pair before submitting: `transform(p["input"]) == p["output"]` for each.
- Keep a `note` field in failed-task files listing the hypotheses already tried — future-you (or a later instance of the same task) will thank you.

## 5. Mindset

My biggest losses came from (a) submitting on degenerate test inputs instead of asking for demos, and (b) fixing a program to fit demos with an over-fitted rule when one more demo would have disambiguated it. My biggest wins came from recognizing a rule family from a past task's memory file and reusing its structure.
