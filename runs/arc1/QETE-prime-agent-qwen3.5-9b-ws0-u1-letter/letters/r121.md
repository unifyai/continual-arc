## How to work a task

**1. Read every demo pair slowly, twice, before writing code.** Print the grids in your head. The most common failure in my run was not bad code — it was committing to a rule after seeing one striking feature and never checking the other pairs. Write the rule in one sentence *first*, then verify it against every kept pair by hand (or by running the program) before you submit anything.

**2. The rule usually lives in one of a small number of families.** In my run these covered nearly everything:

- **Color remapping by role or by value.** Two-color grids: sometimes smaller color → larger, larger → 0 (task-2264bd4e: `hi if v==lo else 0`). Value-based rules beat role-based (majority/minority) ones surprisingly often — I wasted an attempt on majority/minority when min/max was correct.
- **Fill enclosed regions.** Background-colored pockets not touching the border, sometimes only when rectangular (task-3f4fb1a9), sometimes hollow-rectangle interiors with fill color decided by parity of interior area (task-aa5a69a0: even→2, odd→7).
- **Stamp/copy a shape.** Find the largest or rarest component, then stamp its bounding box at every anchor point (task-1b7868f1: every non-bg cell is an anchor, seed bbox centered there) or at every offset where all its cells would land on zeros (task-770f2daf).
- **Geometry of the whole grid.** Split by a solid separator row/column into two blocks, then compare them cellwise (task-026adbf3: 3 where equal, else shared color; task-707635df: 2 where both halves hold their dominant color). Divide by separator lines into blocks and count stray cells (task-48898d06). Tiled/rotated output (task-794e60f6: 2×2 block of the input and its rotations; task-73499f5a: mirrored rows and stacked reflections). Diagonal periodicity: non-zero cells mark residue classes of `(r+c) mod L` or `(r−c) mod L`; fill the whole grid from the residues (task-2e29965a).
- **Extensions from markers.** A dot of one color and a bar of another: draw perpendicular lines from the bar through each dot (task-d4079843). A 1×k shape with a tail: extend along the tail direction (task-3b5f776f — find cells with exactly one neighbor and march outward). Gaps ≤2 between markers get filled, plus the marker bounding box perimeter (task-8625f9bc).
- **Objects relate to a line.** A full 2-line is a mirror or attractor: the object slides until it touches the line, and a new full line of another color appears on its far side (task-77262100).
- **Blocks/scale.** Downsample by 3×3 taking the most common non-special color (task-67dd046a); compare stacked halves and mark agreement.
- **Trivial transforms.** Shift everything one row down (task-efc2fba8). Mark uniform rows/columns (task-47ed202e). Background between equal neighbors becomes a fixed color (task-b7641a67). Rows/cols strictly between two dots become 3 (task-5c839a47). One shift-down, that's all.

Before inventing something exotic, check this list. Check the *simplest* member first: shift, recolor, mirror, fill enclosed. ARC authors love rules that sound too easy.

**3. Identify roles carefully, and prefer structural identifiers.**
- Background = most common color (use `Counter(...).most_common(1)[0][0]`), usually.
- Marker/seed/rare color = least common, or the unique color forming a single component.
- When multiple objects share a color, distinguish them by canonical shape key: `tuple(sorted((y-min(ys), x-min(xs)) for y,x in comp))`. Shapes occurring exactly twice are twin candidates (task-0f6e5a2f recolors the farther twin from a big "arrow" shape).
- Connected components: I used 4-connectivity for same-color components and 8-connectivity when shapes were drawn with thin strokes. Pick per task and check.

**4. Always run your program on all kept pairs before submitting.** This sounds obvious; my one outright loss (task-5997d753) happened because my program reproduced all 6 demo pairs but my hand-derived test prediction didn't come from the program. Derive the test output *by running the program*, never by intuition. If a program reproduces demos but your gut disagrees, trust the program — or find the missing subtlety, which usually means a small special case (a 2-row pocket absorbing its wall row; parity choosing the fill color; an off-by-one at the anchor).

## Harness tactics

- **Save memories early and update them.** One JSON per task under `programs/task-<id>.mem.json` with the rule in a sentence plus file paths. On later encounters with the same task ID, you go straight to a known-correct program. Two of my solved tasks were re-encounters; the memory paid off instantly.
- **Keep pairs you can verify.** The `task-*.json` files are your regression suite. Every edit to a program must keep all kept pairs passing.
- **Failed predictions are information.** I kept `task-1b7868f1_failed.json` with a note listing untried anchor choices. When a submission fails, diff your output against whatever feedback you get, record what was wrong, and enumerate the *next* candidate systematically (e.g., "anchor at seed bbox center vs. one cell off", "clean anchors vs. shifted by 0→1").
- **Don't burn attempts on variant guessing.** If two rule interpretations both fit the demos, look for a third demo feature that discriminates before you submit. If there is none, pick the simpler one and note the alternative in your memory file for the retry.

## Code patterns worth copying from my files

- BFS/DFS component labeling over a `seen` matrix — it appears in ten of my programs; get it right once.
- Bounding-box helpers: `rs=[p[0] for p in comp]`, `r0,r1=min,max`, then `len(comp)==(r1-r0+1)*(c1-c0+1)` tests "solid rectangle".
- Separator detection: a row is a separator iff `len(set(row))==1`; band segmentation by runs of non-separator indices (see task-8d84fe63).
- Canonical shape key for matching components across the grid.
- For symmetric fills, try `rot90(a, k)` and `np.block` before hand-rolling.

## Honesty about my limits

I did not solve everything. task-5997d753 beat me after 8 wrong attempts: the rule involved partial-row regimes and a full-pattern reference row, and my last prediction was off. When you hit a task that resists, don't spiral — lock in the best-fitting program for the demos, make the *most defensible* test prediction, write down what you tried, and move on. A mediocre submission saved is better than three wild ones burned.

The stream will hand you tasks unlike any above. That's fine: the meta-skill is not memorizing rules, it's (a) enumerating the standard families quickly, (b) testing a candidate rule against all pairs before believing it, (c) keeping clean artifacts so the second encounter is free. Do those three things and you will do better than I did.
