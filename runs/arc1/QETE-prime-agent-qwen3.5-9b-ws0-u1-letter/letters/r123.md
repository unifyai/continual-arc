## Recurring rule families (learn these patterns)

Most tasks in this stream fall into a handful of families. When you see a new task, check these first:

**1. Identify roles first.** Almost always: `bg = most common color`. Then look for a rare "marker" color (often 2nd most common or the least common), and "objects" = connected components of other colors. My standard opener:

```python
from collections import Counter, deque
bg = Counter(x for r in grid for x in r).most_common(1)[0][0]
```

Then flood-fill components (4-connectivity usually; sometimes 8 — check whether diagonal-touching cells belong together in the demos).

**2. Bounding-box / rectification (task-b62da9e0).** Components of size ≥ 3 get their whole bounding box filled with their color; everything else becomes background. Simple, common.

**3. Enclosed pockets (task-3f4fb1a9).** Flood-fill background components; those not touching the border are "enclosed." Recolor them (often to 4), sometimes with an extra rule about absorbing an adjacent wall row. Check rectangularity (`len(comp) == bbox area`).

**4. Hollow rectangles (task-aa5a69a0).** A component whose cell count equals its perimeter (`2*(h+w-2)` area formula) is a hollow rect. Fill the interior, with fill color determined by parity of interior area (2 if even, 7 if odd). Parity-based fill colors show up more than once in ARC — keep it in mind.

**5. Line-drawing between markers (task-d4079843, task-8625f9bc, task-5c839a47, task-b7641a67).** A family of "connect the dots" tasks:
- Gaps of size ≤ 2 between consecutive same-color cells in a row/column get filled.
- Cells strictly between two dots (min/max of dot positions in that row or column) become 3.
- A background cell between two identical non-background cells in its row becomes 2.
- Bars + dots: from the bar facing the dots, draw a line to each dot (dot becomes 4); from the opposite bar, draw parallel lines at the same offsets across the whole gap.
This family is "scan each row and column for marker pairs / runs, fill between." Try it early.

**6. Stamp / translate the seed (task-1b7868f1, task-0f6e5a2f, task-770f2daf).** Find the largest non-background component (the "seed"). Then either:
- stamp the seed's bbox at every other non-background cell (anchored by bbox center), or
- stamp the rare-color shape at every offset where all its cells land on 0, or
- among translation-twin pairs of the same shape, recolor the member farther from a special singleton object (an "arrow"/L-shape).
Key tool: canonical shape key = `tuple(sorted((y-min(ys), x-min(xs)) for y,x in comp))` — use it to group components by shape regardless of position.

**7. Split by a uniform separator (task-026adbf3, task-707635df, task-48898d06).** A full row or column of one solid color splits the grid. Then compare the halves cellwise: output 3 (or 2) where both halves agree / both are their dominant color, else background. Sometimes compare blocks and count strays (odd/even counts → 1 or bg). Look for the separator first when the output shape is roughly half the input.

**8. Diagonal periodic fill (task-2e29965a).** Colored cells sit on diagonals `r+c ≡ k (mod L)` or `r-c ≡ k (mod L)`. Collect residue→value from the clues, try both diagonal directions, fill the whole grid. If the input has sparse colored cells over zeros and the nonzero count L is small, try this immediately.

**9. Symmetry/tiling outputs (task-73499f5a, task-794e60f6).** Output = input mirrored/rotated and tiled: e.g. `row[::-1]+row` per row, stacked reversed/original/reversed; or 2×2 tiling with rot90/180/270. Check output dims first: 2n×2n or 3n×? sizes scream tiling.

**10. Color remapping by min/max (task-2264bd4e).** With exactly two colors a<b: a→b and b→0. Important lesson: I first tried majority/minority roles and it was wrong — use min/max of the color values. Verify against demos.

**11. Separators become 2 (task-47ed202e).** Any full-uniform row or column gets recolored to 2. Trivial once seen.

**12. Small shifts (task-efc2fba8).** Everything non-background shifts down one row; top becomes background. Don't overlook the boring answers.

**13. Slide-to-line (task-77262100).** An object slides toward a solid "2" line until adjacent; a full "8" line is drawn on the object's far side. Handle all four orientations.

**14. Downscale abstraction (task-67dd046a, task-bb30ebc2, task-026adbf3).** Output is much smaller than input: 3×3 blocks → majority color (ignoring a noise color like 5); or a lattice of lines defines cells whose corner colors vote. If output dims ≈ input dims divided by 3, count block structure.

## Practical coding habits

- Write `transform(grid)` taking a list of lists of ints, returning the same. Keep it pure and dependency-light (collections, maybe numpy for bincount).
- Test it against every pair in your `.json` file in a loop; print mismatches cell-by-cell, not whole grids.
- When a rule almost works, diff the output against the expected and look at *where* it differs — the diff region usually reveals the missing sub-rule (like my "2-row pockets also absorb the wall row below them" addendum).
- When several rules fit, prefer the one that also explains *which cells are left unchanged* — unchanged regions are as informative as changed ones.
- Beware overfitting: a rule keyed to exact colors (e.g. "fill with 4") generalizes better than one keyed to positions. But also beware underfitting: my parity rule (even→2, odd→7) looked arbitrary until the demos confirmed it twice.

## Handling test inputs you can't verify

- Derive the test prediction *only* from a program that reproduces all demos. Never hand-craft a test answer.
- If the demos leave two plausible rules, request demos before submitting. One extra demo request is cheaper than a wrong submission.
- If you must choose, prefer the rule with a simpler mechanism over one tuned to incidental numbers (I lost a task to a coincidental offset match).

## Mindset

The tasks look diverse but the toolkit is small: components, bounding boxes, separators, symmetry, periodicity, between-ness. Ask, for each new grid, in order: (a) what's background? (b) what are the objects and their shapes/sizes? (c) is there a separator or lattice? (d) do output dims hint at tiling, halving, or scaling? (e) what's unchanged? Most answers are one of the families above, possibly combined.
