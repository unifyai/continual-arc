## What worked, rule by rule (reusable patterns)

Read these carefully — ARC tasks recur and are drawn from a limited family. These are rules I *verified* against demos:

- **Enclosed pockets → 4** (task-3f4fb1a9): flood-fill background components; ones not touching the border and *solid rectangular* get recolored to 4. Beware: only rectangular pockets, and a 2-tall pocket also absorbs its bottom wall row if the row below the wall is background.
- **Stamp a shape into empty slots** (task-770f2daf, task-1b7868f1): find the minority-colored shape, get its bbox pattern, stamp it at every anchor (every all-zero region of that size; or every non-bg cell, translated so the seed's bbox center lands on the anchor).
- **Two colors: smaller→larger, larger→0** (task-2264bd4e). Lesson: *always test both a role-based hypothesis (majority/minority) and an order-based one (min/max color) against the demos.* Roles failed here; min/max worked.
- **Twin-shape selection** (task-0f6e5a2f): among pairs of identical shapes (same canonical form, occurring exactly twice), pick the pair whose nearer member is closest to a distinguished large shape, recolor the *farther* member to that shape's color. General lesson: when one object is special (biggest, unique, a line/arrow), the transformation usually relates other objects to it by **distance**.
- **Symmetry expansion** (task-73499f5a, task-794e60f6): output = block(reversed rows, mirrored rows, tripled) or a 2×2 block of the input and its rotations. When output is 2×/3×/4× input size, think *tiling with the input transformed*.
- **Line intersection extraction** (task-bb30ebc2, task-48898d06): grid of repeated blocks separated by solid uniform lines; compress each block to a single cell (by corner color agreement, or by parity/count of stray color, or majority color). Check separators both as rows and as columns; output shape = (number of blocks) not (number of separator lines).
- **Diagonal periodic fill** (task-2e29965a): non-zero cells define a color per (r+c) mod L or (r−c) mod L residue; fill the whole grid. Try both diagonals.
- **Diagonal/anti-diagonal line sliding** (task-efc2fba8, shift-down): simple shifts of the non-background pattern by one; top row becomes background.
- **Collision / AND of two regions** (task-707635df, task-026adbf3): grid split by a solid separator into A and B; output = where they agree (or where both non-zero), recolored, else a common color.
- **Gaps ≤ 2 between markers get filled** (task-8625f9bc): fill small gaps between marker cells along rows/columns, plus the bbox perimeter of the marker set. Small constant thresholds (2, 3) are common; try them.
- **Hollow rectangles: interior parity fill** (task-aa5a69a0): fill interior with 2 if area even, else 7. Parity rules exist!
- **Background cell with identical non-bg neighbors** (task-b7641a67, task-5c839a47): bg between two identical markers in a row → 2; or bg strictly between two dots (row OR column) → 3.
- **Object slides to a line; a second line is drawn on the far side** (task-77262100).
- **Bars and dots with perpendicular rays** (task-d4079843): from one bar draw perpendicular lines through each dot (endpoint becomes 4); from the mirrored bar draw the same-offset lines spanning the gap.
- **Fill the bounding box of each component of size ≥ 3; erase the rest** (task-b62da9e0).
- **Copy the one "broken" block's pattern everywhere** (task-8d84fe63): find the block with the most non-mode cells; propagate it.
- **Endpoint rays** (task-3b5f776f): degree-1 (endpoint) cells of small shapes shoot rays along their direction to the grid edge.
- **Uniform rows/cols recolored to a constant** (task-47ed202e).
- **Row/column ray casting to nearest obstacle** (task-b7641a67 output shows per-row segments with the same fill pattern).

## Meta-heuristics — how to find the rule when you don't know it

Work through this checklist in order; it covers the vast majority of tasks:

1. **Count colors.** Background = most common. Usually one or two minority colors matter. If exactly two non-bg colors, check "A→B, B→0" and "both map to one color" hypotheses.
2. **Compare shapes.** Is output the same size as input? Same size ⇒ local recoloring or filling. 2×/3×/4× in one or both dims ⇒ tiling/extension (mirror, rotate, repeat-reverse).
3. **Find the objects.** Connected components (4-conn vs 8-conn — try both). Look for: a unique largest object, twins (two identical shapes), singletons, dots, lines/bars (components with aspect ratio ≥ 3).
4. **Check global structure:** solid uniform separator rows/columns (blocks), perfect diagonals, periodic patterns.
5. **Diff input vs output cell-by-cell.** The set of changed cells is your real signal. Are the changed cells: enclosed regions? between two same-colored cells? on the bounding box of something? at positions adjacent to an object? Ask "what determines *whether* a cell changed" before "what color it became".
6. **Counting and parity:** count of a color mod something, area parity, odd/even positions — these appear surprisingly often.
7. **Directional relations:** nearest object above/below/left/right, distance to the special object, "on the far side of" — the twin/distance rule of task-0f6e5a2f took me several attempts; distance-to-unique-object is a strong prior.

## Failure modes to avoid (my actual mistakes)

- **Don't guess at the test with an unverified rule** (killed task-5997d753). If your program reproduces the demos but the test prediction feels arbitrary (e.g., you extrapolated a period), re-examine; consider requesting more demos.
- **Don't fit a rule to one demo pair.** Cross-check on every pair; the second pair usually kills half your hypotheses.
- **Don't assume the separator is a row** — check columns too (task-707635df needed the column fallback).
- **Don't assume majority/minority role when min/max color works** — test both (task-2264bd4e).
- **A failed task stays failed only for that instance.** Save the failure note (see `task-1b7868f1_failed.json`: I noted which anchors were clean and untried). When the task reappears, read your own notes first — the note "sub1==sub3 duplicate" saved me from repeating an identical wrong submission. Never submit the same wrong grid twice.
- **Duplicate submissions waste attempts.** Before submitting, hash/compare against previous submissions for the same task.

## Code habits

- Always copy the grid (`out=[row[:] for row in grid]`) and mutate the copy.
- BFS/DFS component-finding boilerplate (I wrote it ~15 times — memorize it):

```python
from collections import deque, Counter
def comps(g, color_pred):
    H,W=len(g),len(g[0]); seen=[[False]*W for _ in range(H)]; out=[]
    for r in range(H):
        for c in range(W):
            if seen[r][c] or not color_pred(g[r][c]): continue
            q=deque([(r,c)]); seen[r][c]=True; comp=[]
            while q:
                y,x=q.popleft(); comp.append((y,x))
                for dy,dx in ((1,0),(-1,0),(0,1),(0,-1)):
                    ny,nx=y+dy,x+dx
                    if 0<=ny<H and 0<=nx<W and not seen[ny][nx] and color_pred(g[ny][nx]):
                        seen[ny][nx]=True; q.append((ny,nx))
            out.append(comp)
    return out
```
