## 1. The general workflow that works

For every task, in order:

1. **Write out the demo pairs to a JSON file** at `programs/task-<id>.json` as soon as you get them. Include the test input there too (in a separate field or entry) so you never lose it if the context gets long.
2. **Study the pairs before writing any code.** Compare input and output cell by cell. Find the *differences*. Ask: what changed? Where? By how much? Most rules are simple: a shift, a recolor, a fill, a copy, a mirror, a stamp.
3. **Write the program** in `programs/task-<id>.py` with a function `transform(grid)` taking a list of lists of ints and returning the same.
4. **Test it against every kept demo pair before submitting.** If it doesn't reproduce all of them, don't submit — fix the program first. A wrong submission burns an attempt; some tasks cap you (I hit caps at 8 attempts twice and it was fatal).
5. **Submit the test prediction**, then save a memory file (e.g. `memory_task-<id>.json` or a `.mem.json`) recording the rule in one sentence and pointing at your files. Future-you will thank present-you when a variant of the same task reappears.

**Do not over-engineer the rule.** My best results came from the simplest rule consistent with all demo pairs. When two rules both fit the demos, pick the simpler one and reason about which generalizes to the test.

## 2. Recurring rule families I met (and their shapes)

Learn these templates; a large fraction of ARC tasks fall into one:

- **Recolor by a simple mapping.** Keep one color, zero out another (`task-2264bd4e`: map lower color → 0, keep higher). Check the multiset of colors first; often only one thing changes.
- **Shifts and stamps.** (`task-efc2fba8`: shift all non-background cells down one row; `task-1b7868f1`: largest non-bg component is a "seed"; every other non-bg cell is an anchor, stamp the seed's bounding box translated so the seed center lands on the anchor). When a big shape coexists with small markers, the small ones usually say "copy me here."
- **Fills and region completion.** (`task-3f4fb1a9`: fill enclosed rectangular pockets of background with 4, with a special extension rule for 2-tall pockets; `task-8625f9bc`: fill the bounding-box border of marks with 2 and complete broken straight interior lines; `task-5c839a47`: draw 3 strictly between min and max of the rarest color along each row and column). "Connect" and "enclose" rules are very common.
- **Diagonal/line extension.** (`task-3b5f776f`: extend every same-color run of length ≥2 along its diagonal (r−c) and anti-diagonal (r+c), filling background until blocked).
- **Block structure / separators.** (`task-47ed202e`: rows or columns that are one uniform color → all 2; `task-bb30ebc2`: split by full guide rows/cols, output one cell per block using the guides' colors; `task-48898d06`: separator lines split the grid into blocks, block → 1 if it contains strays, else background; `task-67dd046a`: downsample by 3×3, each block → most common non-separator color; `task-026adbf3` and `task-707635df`: split into two halves at a centered full separator line, compare cell-by-cell, output a marker where the halves agree / where both hold their dominant color).
- **Symmetry and tiling.** (`task-73499f5a`: each row becomes reverse(r)+r, then the height triples via reversed/original/reversed; `task-794e60f6`: build a 2×2 block of the input and its rotations — use `np.rot90`; `task-8d84fe63`: replicate a band pattern periodically down the grid; `task-2e29965a`: infer a periodic color pattern along anti-diagonals (i+j mod p) from the sparse colored cells).
- **Movement toward a line.** (`task-77262100`: an object moves flush against a full line of color 2 on its side, old spot becomes background, and a full line of 8 is drawn on the far side of the object).
- **Selection: which object gets changed.** (`task-0f6e5a2f`: among exact-translation twin pairs of the same canonical shape, pick the pair whose nearer member is closest to a special "arrow" object; recolor the *farther* member). When multiple same-shaped objects exist, the discriminating feature is usually position — distance to a special object, touching an edge, being clipped by a border, etc.
- **Growth/continuation from clipped patterns.** (`task-5997d753`: two stacked copies of a pattern, one clipped at the right edge; fill the clipped copy's extension in color 1 using the best-shift alignment with the full copy; `task-770f2daf`: the rarest color's bounding-box pattern is stamped into every all-background box of the same size).
- **Morphology.** (`task-b62da9e0`: components ≥3 cells get their bounding box filled with their color, everything else → background; `task-aa5a69a0`: hollow rectangles ≥3×3 get their interior filled with 2 if area even, 7 if odd — check `len(comp) == perimeter` to detect a rectangle outline).
- **No-op / identity.** Some demos are nearly unchanged (`task-3b5f776f` pair 3 and 4, `task-b7641a67` where nothing falls between markers). Don't invent changes that aren't there; if the demos show the identity for certain configurations, your program must return the input unchanged in those cases. My `task-efc2fba8` candidate that shifted a big blob failed precisely because the demos showed small shapes only shifting one row — the simplest rule won.

## 3. Code patterns to just copy

**Background detection:** `bg = Counter(v for row in g for v in row).most_common(1)[0][0]`. Almost every task needs it. In these tasks background was sometimes 0, sometimes 3/4/5/6/9 — never assume 0.

**Connected components (4- or 8-conn):** write it once, reuse it. 8-connectivity is the right default for touching shapes (I used 8-conn in `task-1b7868f1`); 4-conn for region fills. Decide from the demos whether diagonal touching counts as one object.

**Canonical shape key** for comparing objects regardless of translation:
```python
def skey(cl):
    ys=[y for y,x in cl]; xs=[x for y,x in cl]
    return tuple(sorted((y-min(ys), x-min(xs)) for y,x in cl))
```
Group objects by this key; if a shape occurs exactly twice, that's a "twin pair" and the rule almost always involves choosing between the twins by some positional criterion (nearness to a special object, edge-touching, size tiebreak).

**Bands / segments between separator lines:**
```python
def segs(sz, seps):
    out=[]; s=0
    for e in seps+[sz]:
        if e>s: out.append((s,e))
        s=e+1
    return out
```
and run-length band grouping (consecutive indices) for stripes.

**Full uniform rows/cols:** `rb=[r for r in range(H) if len(set(g[r]))==1]`, same for columns. Use for both detecting separators and detecting lines-to-recolor.

**Counter for color counts** plus `most_common` for background, `most_common()[-1]` for the rarest color (the "dot"/marker color in fill-between tasks).

**Pattern matching with best shift:**
```python
def best_shift(pa,pb):  # pa,pb are sets of columns
    return max(sum(1 for c in pa if 0<=c+s<W and c+s in pb) for s in range(-W,W))
```
Use majority-vote over many row pairs to pin down a shift robustly (I collected shifts across rows and took `Counter(...).most_common(1)` — noise-proof).

**Bounding box:** `r0,r1,c0,c1 = min(ys),max(ys),min(xs),max(xs)` and `len(comp)==(r1-r0+1)*(c1-c0+1)` to check "solid rectangle."

## 4. Traps that cost me attempts

- **Don't trust the first plausible rule.** I burned 8 attempts on `task-5c839a47` because the test had a *single* dot, and every extension I tried (identity, cross, row-only, column-only, mirroring) was wrong. Lesson: if your test input has a configuration the demos never cover (a lone dot, an empty region, an object touching an edge), **request demos early** if the harness allows it, and think hard about what the rule means for that degenerate case before submitting.
- **Keep a failed-attempts note file** (like my `task-1b7868f1_failed.json`) listing every prediction you've tried, so you don't resubmit a duplicate — I nearly wasted an attempt on an exact duplicate prediction.
- **Degenerate inputs.** A 1×N or N×1 input is likely a "roll out" symmetry task. A square input with sparse colored cells is likely a periodic-tiling inference task. A tall grid with two dense horizontal bands is likely the clipped-pattern-completion task. Recognize the shape of the input *before* reading the cells.
- **The demos define the rule; the test defines the config.** If a demo output equals its input except in one 4×4 pocket, the rule lives in that pocket. Diff aggressively.
- **Multiple candidate separators:** when scanning for a full uniform separator row/col, check that it actually splits the grid into two nonempty same-size halves (centered: `2*r+1 == H` or `2*c+1 == W`) — otherwise you'll match decorative lines.
- **Verify every kept pair, not just one.** A rule that fits 3 of 4 demos is wrong. And after the harness gives you feedback (test passed or rejected), record it in memory with the *final* rule statement in one or two sentences — the compressed rule is what helps later.

## 5. Practical habits

- Use numpy when it shortens code (`np.rot90`, `np.array`, bincount for background), but plain Python is fine for everything.
- Always copy: `out=[row[:] for row in grid]`, then mutate. Never mutate the input in place — some tasks need original values while writing output.
- Name colors semantically in comments (`bg`, `dot`, `seed`, `bar`, `arrow`) — it makes rule bugs obvious.
- Keep grid-printing simple: when reading large grids, work with digit strings row by row; the harness format ("grid HxW" followed by rows of digits) is dense — transcribe carefully, a single wrong digit can make a whole rule invisible. Double-check dimensions (H rows, W digits each).
- If a task stumps you, write down what you *know* (which cells change, which never change) before guessing. Cells that never change across all demos constrain the rule enormously.
- And again: **save memory after every task** — a one-line rule, the file paths, whether it reproduced all pairs, and any lesson. The next task that reuses that rule family will go much faster.

You are capable of more than you think on these. Most rules are visible in ten minutes of careful diffing. Be patient, be systematic, verify before submitting, and write everything down.
